# Планка якості в CI

**Гейт:** `npm run check:quality` (`scripts/check-quality.mjs`) · **крок у CI:** джоба `checks`,
поряд із `check:css`, `check:docs` і `check:db` · **леджер боргу:** `scripts/quality-baseline.mjs`

Гейти перевіряли, що код **компілюється**, а не що він потрібен. Цей крок перетворює правила з
тексту на крок збірки: оком рецензент бачить diff, а не файл на 443 рядки, який виріс із 200 за
десять комітів.

## Чотири правила

| # | Правило | Джерело | Що вважається порушенням |
|---|---|---|---|
| 1 | **Кристалева ясність** | `AGENTS.md` §3 | файл > 400 рядків — помилка; > 200 — попередження |
| 2 | **Нативні діалоги** | `AGENTS.md` §4 | будь-який `alert` / `confirm` / `prompt` (і `window.…`) |
| 3 | **Висота екрана** | `AGENTS.md` §3 | `100vh` без `100dvh`-фолбеку поруч |
| 4 | **Емодзі в UI** | `AGENTS.md` §4 | піктограма в коді UI замість `<Icon />` |

`dialog.alert(…)` (наш спільний діалог) і оголошення методів у `packages/ui/src/dialog/`
порушеннями не є — перевірка це знає.

- **Дані — не логіка.** Файли з таблицями констант (`icons.tsx`) ліміт рядків не рахує взагалі:
  дробити `icons.tsx` навпіл — шкодити.
- **Символи ≠ емодзі.** `↑ ↓ ✕ ★ ✓ ♑` забороні не підлягають: це типографіка. Перевірка ловить
  саме піктограми (діапазон `U+1F000–U+1FAFF` і селектор варіації `U+FE0F`), інакше вона
  «забороняла» б зодіакальні знаки в контенті.
- **Емодзі в `bot-dev`** не перевіряються свідомо: тексти бота — це контент
  (`bot-dev/src/shared/config/texts.ts`).

## Леджер боргу

`scripts/quality-baseline.mjs` містить те, що вже описано в документації як відкрита робота.
Усе, чого там немає, — нова помилка, і крок `checks` її зупинить.

**Леджер не можна забути оновити:** якщо файл із нього зник із чекауту або вже вписався в ліміт,
перевірка впаде й попросить прибрати рядок. Так борг не може «висіти в списку» після того, як
його закрили.

Те саме правило кристалевості діє й на `docs/`: файл понад 200 рядків ріжеться на теми
([`docs/README.md`](./README.md) — куди саме), понад 400 — помилка `check:docs`.

## Чого тут ще немає

- **Бюджет бандла** (вага чанків оболонок): потребує `vite build` у джобі `checks`, тобто зміни
  самого пайплайну — вносити окремо й з окремим зеленим прогоном.
- **Поріг покриття для нових модулів** — перший кандидат: читачі контенту (`scenarios` — бот,
  платформа, адмінка; див. `CONTENT_MODEL.md`).

## Як запускати

```bash
npm run check:quality   # планка (той самий крок у CI)
npm run check:css       # «клас без правила»
npm run check:docs      # мертві посилання й шляхи в документації
npm run check:db        # схема D1 поє реєстр
```

Усі кроки стоять у джобі `checks` перед `npm test`: червоний гейт блокує деплой усіх чотирьох
воркерів так само, як червоний тест.
