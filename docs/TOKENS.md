# Токени вигляду

**Джерело правди — CSS:** `packages/shared/src/styles/tokens.css` (світла схема й мірки) і
`themes.css` (темна). Тут **що означає** кожен токен, бо CSS цього не пояснює; перелік
класів-кирпичиків не дублюється — сам CSS і `npm run check:css`. Нумеровані правила вигляду —
[`DESIGN_SYSTEM.md`](./DESIGN_SYSTEM.md).

Яким мусить бути стиль (один, сучасний, дружній) — [`STYLE.md`](./STYLE.md).

Токументи винесено з `DESIGN_SYSTEM.md`: токени — це **словник значень**, а правила — **накази**,
і разом вони перевищили межу редагування.

## Поверхні й текст

| Токен | Призначення |
|---|---|
| `var(--bg-page)` | Фон **екрана**: плоский колір, той самий, що йде нативному хрому Telegram (`= var(--chrome-header-bg)`). Ним малюються `body`, `.wb-app`, `main`, `.page-zone*`, `.wb-splash`, `.wb-auth` |
| `var(--bg-home)` | Градієнт-підкладка **поверхонь** (картки, панелі). Площину екрана ним не малюємо: плоский колір клієнта не дорівняє градієнту — лишився б шов |
| `var(--bg-0)` … `var(--bg-4)` | Поверхні від підкладки до hover |
| `var(--text-primary)` / `--text-secondary` / `--text-muted` | Текст: основний / другорядний / підказка |
| `var(--text-inverse)` | Текст на акцентній плашці |
| `var(--surface)` / `--surface-hover` / `--surface-active` / `--surface-overlay` | Поверхні карток, стани й скрим |
| `var(--surface-modal)` | Поверхня **модалки**: у світлій схемі = `--surface`, у темній — сходинка вище за поверхню екрана, щоб вікно не губилось за скримом (`themes.css`; у трьох кольорах людини — сьомий відсоток тексту у фоні) |
| `var(--border)` / `--border-subtle` | Межі: помітна / ледь видима |
| `var(--green)` / `var(--red)` / `var(--yellow)` (+ `--*-dim`) | Успіх / небезпека / попередження |

## Три кольори людини — єдина палітра продукту

| Токен | Призначення |
|---|---|
| `var(--user-bg)` / `var(--user-text)` / `var(--user-accent)` | **Три кольори користувача** (фон / основний / акцент). Ставить `applyColors()` інлайном на `<html>` разом із `data-colors`, читає `user-colors.css`. Усе інше виведено з цих трьох через `color-mix()` |
| `var(--user-on-accent)` | Підпис на акцентній плашці (`= var(--text-inverse)`): той із фону / основного, хто далі від акценту (`onAccentColor()`) |
| `data-colors-mode` (на `<html>`) | Схема, **виведена з фону** (`colorsMode()`): вибирає тіні, скрим, `color-scheme` і світлі варіанти статусних кольорів |
| `var(--accent)` / `--accent-hover` / `--accent-dim` / `--accent-soft` | Акцент: база / hover / **підкладка** (бейдж, обличчя, чип-тег, вибраний рядок таблиці) / підкладка під фокус |

## Поля, хром Telegram, смуги

| Токен | Призначення |
|---|---|
| `var(--field-bg)` / `var(--field-ring)` | **Поле вводу**: колір і м'яка тінь по краях. Межу поля малюють вони, а не лінія. Світла / темна схема — `themes.css` |
| `var(--field-bg-raised)` | Поле **на тлі поверхні чи картки**: біле у світлій схемі, світліше за поверхню — у темній. Похідна `--field-bg` там читалась як заголовок |
| `var(--field-pad-y)` / `var(--field-pad-x)` | **Відступи поля вводу**: `padding` пише лише спільний кирпичик (`.wb-input` / `.wb-select` / `.wb-textarea`), з цих токенів. Оголошені раз, у токенах: правило контрола лише читає їх (правило 16, `fields.test.ts`) |
| `var(--chrome-header-bg)` / `--chrome-bottom-bg` | Нативний хром Telegram: шапка клієнта і смуга під футером; синхронізує `shared/app/telegram-chrome.ts`. З трьома кольорами це рівно `--user-bg` (плоский hex — саме тому він іде клієнту як є). Наші смуги (`.wb-app-header`, `.wb-topbar`, `.wb-tabbar`) малюються тими самими токенами на 91% і **без** ліній та тіней |
| `--topbar-h` / `--nav-bar-h` / `--tab-bar-h` | Висоти смуг; `--tab-bar-h` = `--nav-bar-h` + `--safe-bottom` (не перевизначати третім числом) |
| `--appbar-h` | Висота закріпленого хедера; від неї відлічують закріплені речі сторінки (шапка таблиці стає під хедером). Початкове значення — `--topbar-h` + `--safe-top`, але справжнє публікує сам хедер (хук `useAppBarHeight`): `min-height` — підлога, і на збільшеному шрифті два рядки назви роблять його вищим |
| `--subbar-h` | Висота другої смуги футера |
| `--sidebar-w` / `--sidebar-w-collapsed` / `--sidebar-w-vw` / `--scrim` | Геометрія навігації (однакова в обох оболонках) |
| `--safe-top` / `--safe-bottom` | Краї екрана: `env(safe-area-inset-*)` + `--tg-safe-area-inset-*` від Telegram. Не 0 лише тоді, коли в `index.html` є `viewport-fit=cover` |
| `--max-content` | Максимальна ширина контенту |

## Рядок, картка, заголовок

Мірки цих трьох деталей живуть **тільки тут** — екран їх не задає: поки кожен брав свої
числа, назва акордеона була 22px, пункт меню — 14px, а «частина сторінки» — 13, 15 і 17px
у трьох місцях.

| Токен | Призначення |
|---|---|
| `var(--row-bg)` / `--row-radius` / `--row-pad-y` / `--row-pad-x` / `--row-gap` / `--row-min-h` | **Рядок списку**: пункт меню, акордеон «Розвитку», «Обране», група трекерів, розмова |
| `var(--row-title-size)` / `--row-title-weight` / `--row-title-color` / `--row-icon-color` / `--row-trailing-color` | Підпис рядка, знак перед ним і шеврон: одна вага на всі списки |
| `var(--card-bg)` / `--card-radius` / `--card-pad` / `--card-gap` / `--card-shadow` | **Картка**: поверхня, радіус, береги, крок вмісту й тінь. Рамки немає — місце відділяє поверхня (правило 15). Значення живуть тут, а не в правилі картки: «заповнена поверхня» — це `--card-shadow` |
| `var(--heading-section-size)` / `--heading-section-weight` | **Частина сторінки** («На що звернути увагу», «Ти не один»): одна міра на всі екрани; розмір дає клас ролі, а не тег (правило 16, `typography.test.ts`) |
| `var(--heading-card-size)` / `--heading-card-weight` | Назва **картки** (`.wb-card-title`) |
| `var(--heading-group-size)` / `--heading-group-weight` | **Підпис групи** списку |

Стежать `styles/rows.test.ts` і `styles/surfaces.test.ts`: власний `padding`, `font-size` чи
`border-radius` у цих правил — падіння, як і **клас, описаний у двох файлах стилів**
(`.wb-profile` був і карткою акаунта, і блоком результату, тож блок результату успадковував
чужий градієнт, тінь і береги).

## Типографіка, мірки, рух

| Токен | Призначення |
|---|---|
| `var(--font-ui)` / `--font-display` / `--font-mono` | Основний / заголовковий / моно |
| `var(--text-xs)` … `--text-6xl` | Шкала кеглів: 11 / 13 / 14 / 16 / 18 / 22 / 28 / 32 / 36 / 40 / 48 |
| `--focus-ring-width`, `--focus-ring-offset`, `--focus-ring-color` | Клавіатурний фокус: одна рамка на продукт |
| `var(--radius-xs)` … `--radius-xl`, `--radius-full` | 2 / 4 / 6 / 8 / 12 / 16px і 9999px (пілюлі) |
| `--sp-0` … `--sp-16` | Відступи 4px-кроком |
| `--btn-pad-y`, `--btn-pad-x` | Мірки кнопки: `padding` пише лише базове `.wb-btn`, з цих токенів (правило 16) |
| `--shadow-*`, `--elevation-*`, `--duration-*`, `--ease*` | Тіні, рух і пружина |
| `--z-dropdown` < `--z-sticky` < `--z-overlay` < `--z-modal` (400) < `--z-tabbar` (**1100**) < `--z-toast` (1200) | Шари: футер вище за модалки (правило 12) |

**Кегль — лише зі шкали.** `font-size` поза `tokens.css` мусить бути `var(--text-*)`: сирі
`9px`, `12.5px`, `15px` заборонені, бо через них той самий підпис мав на двох екранах різний
розмір. Винятки — `max(16px, 1em)` у полів (інакше iOS масштабує сторінку на фокусі) і `0`.
Той самий сторож тримає кути: `border-radius` — крок `--radius-*`, а не власне число.

**Фокус, рух і палець — наскрізні.** Клавіатурний фокус малює одна рамка з `--focus-ring-*` у
`reset.css` (миша її не показує — `:focus-visible`), а поля лишають своє кільце.
`prefers-reduced-motion` робить переходи миттєвими, а не прибирає їх. Наведення живе лише під
`@media (hover: hover)`: на дотику відповідає `:active`, а не налиплий `:hover`; тап без сірої
плями (`-webkit-tap-highlight-color`), без 300 мс і без масштабу подвійним тапом (`touch-action`),
смуга прокрутки однакова в WebKit і Firefox, а `color-scheme` каже ОС, яка схема ввімкнена. Контрол, менший за 44px
(кнопка закриття, перемикач, ряд керування), на дотиковому пристрої розширюється до 44 —
виглядом або невидимою підкладкою. Стежать `styles/type-scale.test.ts` і `styles/platform.test.ts`.

**Різниця ОС прибрана в `reset.css`, а не на екранах.** iOS і Android малювали власну коробку
навколо поля пошуку — `appearance: none` лишає нашу; iOS не має відкривати меню «Копіювати» на
кнопці (`-webkit-touch-callout`), а підпис контрола — виділятись; автозаповнення Chrome і Safari
не фарбує поле в жовтий чи синій (внутрішня тінь у `:-webkit-autofill`); підказка поля непрозора
(інакше Firefox робив її ледь видимою); подвійний тап не масштабує ні картку, ні рядок
(`touch-action: manipulation` на `body`). Windows «Високий контраст» (`forced-colors`) відкидає тіні,
тож `components.css` додає картці й полю **справжню** межу — без неї поверхня, що трималась на
`--card-shadow`, зникала; `prefers-contrast: more` піднімає приглушений текст і тонку межу на
сходинку вище, не заводячи другої палітри.

**Клавіатура телефона — частина контрола.** Пошук каже `enterkeyhint="search"` і не віддає запит
словнику (`autocomplete`/`autocorrect`/`spellcheck`), а `index.html` обох оболонок несе
`interactive-widget=resizes-content`: на Android без нього смуга вводу лишалась під клавіатурою
(мінявся лише видимий прямокутник), iOS ключ ігнорує. `user-scalable=no` не ставимо — пінч
лишається доступним.

**Виняток із токенів — ігри.** Гра єдине місце, де кольори належать твору, а не застосункові: вона
має власну палітру `--game-*` замість спільної. Правило й межі — [`GAMES.md`](./GAMES.md) §4.
