# Документація проєкту: покажчик

**Один документ = одна тема = один власник факту.** Якщо число потрібне в двох місцях, його
тримає один документ, а інші на нього посилаються. Дубльоване число — це число, яке рано чи
пізно стане неправдою (саме так у документації з'явились «13 голих `100vh`», яких ніколи не
було, і «0 емодзі», яких було 16).

## Куди писати нове

| Що з'явилось | Куди |
|---|---|
| Нове виміряне число | `CONSOLIDATION_PLAN.md` §0 (і більше нікуди) |
| Закрита робота, рішення, знахідка | новий файл `docs/log/journal-<рік>-<міс>-<день>-<тема>.md` + рядок у покажчику `CONSOLIDATION_LOG.md` |
| Нове правило, заборона, конвенція | `AGENTS.md` (відповідний §) |
| Новий гейт або поріг | `QUALITY_GATE.md` |
| Новий токен, клас, іконка | `DESIGN_SYSTEM.md` / `DESIGN_SYSTEM_COMPONENTS.md` |
| Нова таблиця, ендпоїнт, роут | відповідна частина в `sites/` |

## Чому документи маленькі

Правило кристалевості з `AGENTS.md` §3 стосується документації так само, як коду:

| Розмір файлу | Що це означає |
|---|---|
| > 200 рядків | червоний прапорець: різати на теми |
| > 400 рядків | критично |

Причина не в естетиці. **Довгий документ не можна правити акуратно.** Щоб змінити один абзац
у полотні на 1 235 рядків, треба відтворити довгий якір байт-у-байт — і будь-яка невидима
розбіжність (наприклад латинська `i` всередині слова `застосункiв`) робить правку
неможливою, причому мовчки. Саме через це планка якості в CI й леджер боргу стережуть і
розмір файлів.

Дотримуйся правила «один пункт = один коміт» і дописуй історію в `log/`, а не в кінець
наявного документа.
