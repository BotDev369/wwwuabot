# Документація проєкту: покажчик

**Один документ = одна тема = один власник факту.** Якщо число чи правило потрібне в двох
місцях, його тримає один документ, а інші на нього посилаються.

## Де що лежить

Таблиця — це **реєстр документів**: кожен `.md` із `docs/` мусить мати тут рядок, інакше документ не

## Бюджет розміру — два різні, і в кожного є права

Код і документація — різні жанри, тому ліміт у кожного свій. Межі тримають гейти, а не пам'ять
автора: код — `npm run check:quality`, документи — `npm run check:docs`. **Самі числа, межі й де
живуть права — [`QUALITY_GATE.md`](./QUALITY_GATE.md)**; тут — чому воно так.

**Право на більше — це не виняток для улюбленця, а записана причина.** Файл, який справді не
ділиться, отримує зсунуту м'яку межу разом із поясненням, чому саме він: без причини право через
місяць «оптимізують» назад. Сьогодні таке право **одне**: [`../AGENTS.md`](../AGENTS.md) — єдина
інструкція для агентів, яку читають повністю одним заходом. Правило, яке перестало потребувати права,
право **втрачає**: документ, що вліз у типову межу після поділу на теми, зі списку зникає (так
звільнився `DESIGN_SYSTEM.md`, коли поверхні й колекції поїхали у свої документи).

**Жорстка межа не зсувається нікому:** файл, який її перейшов, не читають — його гортають.

- **Вага рахується разом із рядками.** Полотно з довгих абзаців і полотно з коротких — однакова
  проблема при однаковій кількості рядків, і саме вага (а не рядки) з'їдає контекст.
- **Генеровані документи розмір не нормують** — їхній розмір визначає код, а гейт перевіряє
  **свіжість**: [`API.md`](./API.md), який розійшовся з роутером, — помилка.
- **Файли-дані** (таблиці констант на кшталт `icons.tsx`) у бюджет коду не рахуються: дробити їх
  навпіл — шкодити.
- **Правило росте не текстом, а адресою.** Нове правило — рядок у `AGENTS.md` (з причиною одним
  реченням); тема, довша за три рядки, їде в окремий маленький `.md` за покажчиком.
- **Межа редагування — реальна стеля.** Інструменти редагування беруть лише перші ~35 KB файлу: довший **читається**, але правка в хвості «не знаходить» текст, і це приходить мовчки. Тому документ понад 34 KiB — помилка `check:docs`, а не попередження: це не смак, а межа інструмента.
- **Реєстр руками не пишуть.** Перелік класів, ендпоїнтів, таблиць, іконок дрейфує першим, тому
  його або друкує гейт (`check:css`, `check:db`, `doc:api`), або він живе в одному місці й
  перевіряється на живість (шляхи, посилання, згадки з коду, `AGENTS.md §N`, рядок у цьому покажчику
  — теж `check:docs`).
- **Дати й розміри в покажчику не стоять.** Дату тримає `git log`: документ правлять комітом, а не
  полем у таблиці, тож поле старіє першим і бреше тихо. Розмір друкує сам `npm run check:docs`
  (скільки файлів, найбільший, разом, хто за межею редагування) у кожному прогоні — вписане число
  поступається місцем тому, яке завжди правдиве.

Причина, чому бюджет взагалі є: **довгий документ неможливо правити акуратно.** Щоб змінити абзац у
полотні, треба відтворити довгий якір байт-у-байт — і будь-яка невидима розбіжність робить правку
неможливою, причому мовчки. Тому стеля стоїть **нижче** за реальну шкоду: вона робить зростання
видимим за місяць до того, як документ стане некерованим, а не в день, коли правити вже нічого.
