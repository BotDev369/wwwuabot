# Документація проєкту: покажчик

**Один документ = одна тема = один власник факту.** Якщо число чи правило потрібне в двох
місцях, його тримає один документ, а інші на нього посилаються.

## Де що лежить

| Документ | Відповідає за |
|---|---|
| [`../AGENTS.md`](../AGENTS.md) | **правила роботи**: архітектура, межі, доменні терміни, заборони, конвенції, гейти, відкрита робота. Єдиний документ, який читають повністю |
| [`DESIGN_SYSTEM.md`](./DESIGN_SYSTEM.md) | токени, правила вигляду (нумеровані — на них посилається код), розміри, теми, де що лежить. Класи-кирпичики — `AGENTS.md` §3, а самі правила — у CSS і `check:css` (перелік у документі дрейфує) |
| [`DATA_MODEL.md`](./DATA_MODEL.md) | таблиці D1: власник, хто створює, хто читає; як виконати SQL; гейт `check:db` |
| [`CONTENT_MODEL.md`](./CONTENT_MODEL.md) | контент сторінок: одне сховище (`scenarios`), адреса — одна сутність `slug` |
| [`QUALITY_GATE.md`](./QUALITY_GATE.md) | планка в CI: чотири правила, леджер боргу, чого ще немає |
| [`MONITORING.md`](./MONITORING.md) | health, логи, Sentry, UptimeRobot; що робити при падінні |
| [`HOME_PAGE_DATA.json`](./HOME_PAGE_DATA.json) | дані головної сторінки (вміст `page_data`) для міграції `2026-09-14-scenarios-03-home-page.sql` |

## Куди писати нове

| Що з'явилось | Куди |
|---|---|
| Нове правило, заборона, конвенція | `AGENTS.md` (відповідний §) |
| Нова тема, яка заслуговує документа | новий маленький `.md` у `docs/` + рядок у таблиці вище |
| Новий гейт або поріг | `QUALITY_GATE.md`; якщо гейт про одну тему — документ цієї теми (напр. `check:db` — у `DATA_MODEL.md`) |
| Новий токен, правило вигляду | `DESIGN_SYSTEM.md` (номер правила не змінювати — на нього посилається код) |
| Новий клас | спочатку правило в `packages/shared/src/styles/`, тоді вжиток; перелік — `AGENTS.md` §3 |
| Нова іконка | `packages/shared/src/components/icons.tsx` (`IconName` — єдине джерело) |
| Нова таблиця або колонка D1 | реєстр `packages/shared/src/database/tables.ts` + рядок у `DATA_MODEL.md` |
| Правило адреси, діплінка чи параметрів URL | `CONTENT_MODEL.md` + код `packages/shared/src/content/resolve.ts` |
| Новий ендпоїнт, роут | `AGENTS.md` §5 (карта доступу) + контролер у `api-dev/src/controllers/` |
| Виміряне число | **нікуди**: його друкують самі гейти (`npm run check:css` / `check:docs` / `check:quality` / `npm test`) |

## Чому документи маленькі

Правило кристалевості з `AGENTS.md` §3 стосується документації так само, як коду:

| Розмір файлу | Що це означає |
|---|---|
| > 200 рядків | червоний прапорець: різати на теми |
| > 400 рядків | критично |

Причина не в естетиці: **довгий документ не можна правити акуратно.** Щоб змінити один абзац у
полотні, треба відтворити довгий якір байт-у-байт — і будь-яка невидима розбіжність робить
правку неможливою, причому мовчки. Розмір, мертві посилання й шляхи з коду перевіряє
`npm run check:docs`.
