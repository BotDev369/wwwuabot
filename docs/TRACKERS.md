# Трекери

**Один універсальний трекер на всі мірки.** Звичка, вода, вага, настрій, витрати — це не різні
сутності, а різні одиниці одного ряду «день → число». Тому вид трекера задають дані (`unit`,
`step`, `goal`, `min`, `max`), а не гілка в коді: нова мірка не потребує нової таблиці, екрана чи
аналітики.

## Стандартні трекери

Каталог — `TRACKER_CATALOG` у `packages/shared/src/trackers.ts` (кроки, вода, сон, вага, настрій,
енергія, рух, читання, витрати). При першому вході сервіс створює їх людині (`INSERT OR IGNORE` +
`UNIQUE (owner_id, key)`), тож повторний вхід нічого не дублює, а прибраний трекер не воскресає.
Власний трекер додають формою на `/trackers?new=1`: назва, одиниця, ціль (не обов'язково), крок.

## Дані

- `trackers` — рядок на мірку: `owner_id`, `key`, `title`, `unit`, `step`, `goal`,
  `min_value`/`max_value`, `icon`, `is_builtin`, `is_active`.
- `tracker_entries` — рядок на **дотик**: `day` (`YYYY-MM-DD`), `value`, `note` і `logged_at` (момент
  запису із секундами, його ставить SQLite). За день може бути скільки завгодно дотиків —
  `UNIQUE (tracker_id, day)` прибрано перебудовою `scripts/migrations/2026-10-17-tracker-entries-*`;
  день у графіку й звіті — їх **сума** (`trackerDayTotals`), а в історії — окремі рядки з часом.
- «Прибрати трекер» — `is_active = 0`: історія лишається в базі, а зі стрічки трекер зникає.

Реєстр — `packages/shared/src/database/tables.ts`, карта — [`DATA_MODEL.md`](./DATA_MODEL.md).

## Екрани

- `/trackers` — компактна стрічка: іконка, назва й **порожнє** поле швидкого запису. Поруч із полем
  з'являється кнопка надсилання, щойно в поле щось введено (порожній дотик — це помилка, а не дія);
  дотик по решті картки відкриває трекер. Іконка й поле — окремі цілі: дотик по полю не
  відкриває сторінку, бо тоді клавіатури не було б.
- `/trackers/:id` — усе інше: запис із датою й нотаткою, вікна 7/30/90 днів, графік із лінією цілі,
  звіт і історія дотиків (день, час, число). Рядок історії підставляє свій день у форму, тож
  записати «за вчора» — це один дотик, а не друга форма.
- Поля значень ніколи не заповнюються дефолтним числом: підказка — одиниця (`л`, `год`), а не чиясь
  ціль. Попереднє значення в полі читають як вже введене, і воно заважає.

## Аналітика

Рахує `trackerReport` (`packages/shared/src/trackers.ts`) з тих самих рядків, що й графік:

- **середнє** — лише дні **із записом**; порожній день не тягне його до нуля;
- **серія** — поточна: рахується від сьогодні (або вчора, якщо сьогодні ще не записано), перерва
  обнуляє;
- **ціль** — дні, де значення ≥ цілі, і частка від вікна;
- **зміна** — середнє проти попереднього вікна тієї ж довжини; без попередніх даних — `null`
  («немає з чим порівняти»), а не 0%.

Числа не дублюються на сервері: API віддає рядки, а серію й звіт рахують спільні чисті функції на
клієнті.

## API

| Метод | Шлях | Що робить |
|---|---|---|
| GET | `/api/user/trackers` | стрічка: трекери + записи останні 30 днів |
| GET | `/api/user/trackers?id=N` | один трекер + історія 400 днів |
| POST | `/api/user/trackers` | власний трекер (назва, одиниця, крок, ціль) |
| DELETE | `/api/user/trackers?id=N` | прибрати трекер (історія лишається) |
| POST | `/api/user/trackers/entry` | новий дотик дня (додає рядок, не править) |
| DELETE | `/api/user/trackers/entry?id=N` | прибрати один дотик |

Ідентичність — лише підписаний `initData`; власника з тіла чи `?user_id=` не існує. Групи
доступу — [`API.md`](./API.md).

## Чого тут ще немає

Тижневих цілей, нагадувань у боті, експорту й публічності: трекери бачить лише власник.
