### 12.09.2026 — планка якості в CI (`check:quality`)

**Проблема не в тому, що код поганий, а в тому, що ніщо не заважало йому псуватись.**
`AGENTS.md` казав: файл > 400 рядків — критично; емодзі в UI заборонені; нативні
`alert`/`confirm`/`prompt` заборонені; `100vh` без `dvh` «стрибає» на телефоні. Усі чотири
правила перевірялись очима — і всі чотири порушувались у коді. Це та сама хвороба, від якої
народився `check:css`: клас без правила не ламає ні збірку, ні тести, його видно лише очима.

**Що зроблено:** `npm run check:quality` (`scripts/check-quality.mjs`) — той самий крок у
джобі `checks`, що й `check:css`. Чотири правила: ліміт рядків файлу (400 — помилка, 200 —
попередження), заборона нативних діалогів, заборона голого `100vh`, заборона емодзі в UI.
Заодно: `no-explicit-any` піднято з `warn` до `error` в усіх п'яти ESLint-конфігах;
`walk` / `isCss` / `isSource` / `ROOT` винесено в `scripts/lib/files.mjs`, щоб два
перевіряльники не тримали дві копії обходу дерева.

**Що гейт знайшов на першому ж прогоні:**

- **16 справжніх емодзі** в кнопках і заголовках обох оболонок, у 7 файлах
  (`PageBuilderPage` 🏗️ 🔧 📋 🔄 📥, `BotSettingsPage` 🤖 🔗 📤, `PageRenderer` 📎 📌 📄,
  `CodeBlock` 📋, `RichTextField` 🔗, `BotRichConstructor` і `ScenarioJsonEditor` ⚠️).
  Усі замінено на `<Icon name="…" />` зі спільного набору, тому розмір тепер керується
  пропом `size`, а не шрифтом емодзі. Прибрано два висячі `U+FE0F`.
- **0 нативних діалогів** — правило вже трималось (33 виклики закрито раніше), тепер
  воно не може повернутись.
- **0 голих `100vh`** — і це виправило число в аудиті: «13 голих `100vh`» (§2.6) виявились
  фолбек-парами `100vh` + `100dvh`, тобто саме тим, як і належить.
- **Друга поправка до аудиту:** «емодзі в UI — 0» (§2.7) на момент написання було **16**.

**Перевірка:** `npm run check:quality` — 0 помилок ✅ · `npm run check:css` — 0 ✅ ·
`npm run lint` — 0/0 з `any: error` ✅ · `npm run typecheck` — чисто на 6 воркспейсах ✅ ·
`npm test` — 182/182 ✅ · `npx prettier --check .` — чисто ✅ · збірки `web-platform-dev`
(CSS 100.71 kB) і `web-admin-dev` (CSS 123.91 kB, окремий чанк `RichTextField` 5.41 kB) ✅

**Підсумок:** борг не «закрито» — він **зафіксований**. `scripts/quality-baseline.mjs`
перелічує файли > 400 рядків, і леджер сам ламає збірку, якщо файл із нього зник або
перестав порушувати. Тобто борг більше не можна забути в списку після того, як його
закрили, — саме на цьому спіткнулась попередня чистка мертвого коду. Першу перевірку ця
механіка пройшла того ж дня: після поділу `sites.service.ts` гейт упав із вимогою прибрати
рядок із леджера.

> **Чому цей запис з'явився із запізненням.** Тоді журнал був одним файлом на 1 235 рядків,
> і додати в нього абзац не вдавалось (я пояснював це «редактор не бачить кирилицю» — це
> було хибне пояснення). Справжня причина: довгий якір у великому полотні не зіставляється
> байт-у-байт, і помилка при цьому мовчки пропускається. Запис внесено 12.09.2026 під час
