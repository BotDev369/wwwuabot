# Стиль: контент — тексти, вигляд — каталог ролей

**Правило одне:** сторінка, модалка й меню не описують, як вони виглядають. Вони
називають **категорію** й **роль**, а колір, розмір, відступ, радіус і рух беруться з
каталогу. Нова сторінка = тексти в базі (`platform_pages.page_data`) + ролі зі списку.

## Чому так

Коли вигляд пише кожна сторінка, той самий блок виглядає по-різному на двох екранах, і
зміна палітри — це пошук кольору по файлах. Коли вигляд один, зміна стилю — правка
одного CSS, а автор сторінки взагалі не думає про кольори.

## Каталог

| Що | Де |
|---|---|
| Категорії й ролі (дані) | `packages/shared/src/ui/role-catalog.ts` |
| Значення ролей (CSS) | `packages/shared/src/styles/role-catalog.css` |
| Демо-вітрина | `/style` в адмінці, `web-admin-dev/src/pages/style/` |

Категорії: гасло, поверхні, навігація, дані, графіки, форми, статуси, порожній стан, рух.
Кожна роль має п’ять ознак:

| Ознака | Значення | Клас |
|---|---|---|
| тон | ink, muted, accent, `data-0`…`data-6`, green, yellow, red | `sc-tone-*` |
| розмір | display, title, head, body, label, number, caption | `sc-size-*` |
| відступ | none, tight, base, loose | `sc-gap-*` |
| рух | none, rise, fade, pulse | `sc-motion-*` |
| радіус | none, sm, md, lg, full | `sc-radius-*` |

Сторінка бере роль функцією `roleClass(role)` — і більше нічого про вигляд не знає.

## Перелік єдиного UI (`/style`)

Сторінка `/style` — **структурований перелік усіх елементів єдиного UI**, а не демо-лендінг:
кирпичики й знаки в розділах (дії, поля, поверхні, вікна, дані, стани, текст, блоки, знаки).
Кожен рядок показує **справжній зразок** із платформеної розмітки, його клас і присуд.
**Розділи згорнуті** — їх розкривають по одному (або «Розгорнути всі»), щоб не гортати
сотні рядків щоразу.

| Присуд | Що означає |
|---|---|
| шаблон в обох оболонках | клас ужито і в платформі, і в адмінці |
| лише одна оболонка | ужито тільки в одній з двох |
| лише в спільному коді | клас живе в `packages/ui` / `packages/shared`, оболонки його не звуть напряму |
| шаблон через Page Builder | блок рендерить спільний `PageRenderer`, а сторінки вживають його тип у даних |
| не вживається | правило є, споживача немає |

**Чому блоки не «лише в спільному коді».** Сторінка не пише `wb-block-hero` руками: її
`page_data` називає тип блоку, а розмітку дає `PageRenderer` зі `packages/ui`. Тому присуд
блоків — «шаблон через Page Builder»: клас ужито в продукті, але через механізм, а не
через розмітку оболонки.

**Блоки — весь реєстр.** Розділ «Блоки сторінки» перелічує **всі типи `BLOCK_DEFINITIONS`**
(`packages/shared/src/constants/block-definitions/`), а не кілька вибраних: генератор читає
`type`, `label`, `icon` і `description` із реєстру, тож новий блок з'являється в переліку сам.
Замість класу рядок показує те, чим сторінка справді вживає блок — `type: "…"`; зразок —
знак блока з галереї модулів, бо вигляд блока залежить від його даних.

**Знаки.** Розділ «Знаки» перелічує весь `ICON_NAMES`; ужиток рахується так само, як у
`icons.test.ts`: файл тримає набір (`<Icon>`, `IconName`, мапа `icons`) і згадує ім'я.

**Власного CSS в оболонках немає.** `index.css` платформи й адмінки — лише `@import`
спільних шарів; правило в `web-…/src` стереже `check:shell-styles` усередині `check:css`.

**Лічильники — з коду.** `scripts/ui-inventory.mjs` рахує, у скількох файлах кожної частини
продукту вжито клас, і пише `web-admin-dev/src/pages/style/ui-inventory.json`. Сторінка
лише показує; сама вона з підрахунку виключена, інакше міряла б власні зразки. Перелік
елементів і зразки — `scripts/ui-inventory-elements.mjs` і `UiSamples.tsx`.

**Зразок не малює нового вигляду:** ті самі класи, що в продукті. Слова — з даних, бо
кирилиця в UI-коді заборонена (`check:texts`). Свіжість переліку ловить `npm run
check:style` (разом із каталогом), перегенерація — `npm run doc:style`.

## Колір

- **Акцент — тільки дія** (кнопка, фокус, активний пункт). Акцент на даних заборонений:
  число, смуга й кнопка починають читатись як одна річ.
- **Дані фарбуються своєю серією** (`--data-1`…`--data-6`). Колір смуги, числа й підпису
  легенди збігається — це та сама серія.
- **Нейтральне — сірим** (`--data-0`): «інше», «скасоване», «приховане».
- **Статуси — зміст, а не серія**: `--green` / `--yellow` / `--red`.
- Назва блока — головна (основний текст), число — другорядне за розміром, але кольорове.

## Заборонено

- інлайн-стилі (`style=`) і власні кольори в розмітці;
- приватний клас під те, що вже має роль;
- другий перемикач теми чи друге меню вигляду;
- таблиця без власного скролу, без закріпленої шапки й першого стовпця;
- вертикальний скрол сторінки, заблокований таблицею.

## Таблиця

Таблиця гортається **сама**: обмежена висота, `overflow: auto` в обидва боки,
`position: sticky` для `thead th` і першого стовпця (це дає `.wb-table-scroll` +
`.wb-table`). Сторінка при цьому їде далі: `.demo-shop-table` ставить
`overscroll-behavior: auto`, щоб край таблиці не замикав гортання.

## Гейти

`npm run check:css` (клас без правила), `npm run check:quality` (моноліти, емодзі,
інлайн-стилі — `check:inline`), `npm run check:style` (свіжість каталогу CSS).

## Мобільна версія — перша

Сторінка панелі не має власного скролу документа: каркас тримає `overflow: hidden`,
тож прокрутку дає **сама сторінка** (`.sc-page`, `.wb-page-scroll`). Без цього довгий
вміст обрізається, і сторінка «не гортається».

- Перевірка на **390 і 320 px**: `scrollWidth === innerWidth` (немає виносу вбік),
  прокрутка досягає низу, таблиця їде вбік **усередині себе** й не замикає сторінку.
- Блоки у flex-колонці з прокруткою не стискаються (`flex: 0 0 auto`) — інакше герой
  і картки ріжуться до висоти рядка.
- Герой і картки не ріжуться, підписи не обрізаються, перемикачі стоять окремим рядком.
