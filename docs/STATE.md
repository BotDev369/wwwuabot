# Стан проєкту: що розійшлося з документацією і як це закривається

**Власник факту:** відкриті розходження між документами й кодом, порядок їх закриття та питання,
які чекають рішення власника. Правила роботи — [`../AGENTS.md`](../AGENTS.md), покажчик —
[`README.md`](./README.md).

**Навіщо окремий документ.** Гейт `npm run check:docs` перевіряє **форму** — мертві посилання й
шляхи, рядок у покажчику, межу редагування, свіжість генерованого. Він не перевіряє
**істинність тверджень**: документ може бути зеленим і при цьому описувати таблицю, якої вже
немає. Цей файл тримає саме те, що гейт не бачить, доки воно не закрито. Закритий рядок
**зникає**, а не перетворюється на історію.

## Відкриті розходження

| Що | Чим доведено | Крок |
|---|---|---|
| Дев'ять документів перевищують власну м'яку межу, а «право на більше» має лише `AGENTS.md` | попередження `npm run check:docs` (перелік друкує сам гейт) | 1 |
| Виміряні числа вписані в тексти (`TEXT_AUDIT`, `CLOUDFLARE_AUDIT`, `D1_QUERY_COST`, `RESOURCE_PLAN`) | суперечить правилу «числа друкують гейти» з [`README.md`](./README.md) | 1 |
| Мертвий CSS: клас має правило, але не згадується в коді навіть підрядком | `npm run check:css` друкує перелік; цілі поверхні (старий Page Builder, каталог стилю, прев'ю Telegram) видалені, стилі лишились | 2 |
| Cloudflare: дев'ять ресурсів без жодної згадки в коді й конфігах | `wrangler` + пошук імені в `*.ts`, `*.toml`, `*.mjs`, `*.json`; реєстр — [`RESOURCE_PLAN.md`](./RESOURCE_PLAN.md) | 4 |
| Легасі-хвіст у дев-базі: зайві таблиці, бекап-копії й колонки | [`DB_LEGACY.md`](./DB_LEGACY.md) | 5 |
| Немає машинної карти репо: агент перечитує файли, щоб знайти власника теми | розмір репо й покажчик документів — ручні | 6 |
| Правило «доступи вже в оточенні» живе одним рядком у кінці `AGENTS.md` — а той стоїть упритул до межі редагування, тож розширити правило ніде | `npm run check:docs` (`EDIT_LIMIT`, `BUDGET_RIGHTS`) | 6 |
| Гейт документації не ловить легасі-слова в прикладах і вписані виміри | [`../.github/workflows/d1.yml`](../.github/workflows/d1.yml) тримав приклад SQL до видаленої таблиці, і `check:docs` був зелений | 7 |

## Порядок роботи

1. **Власники фактів.** Пройти документи, що тримають факти про продукт ([`PLATFORM.md`](./PLATFORM.md),
   [`DATA_MODEL.md`](./DATA_MODEL.md), [`STORAGE.md`](./STORAGE.md), [`QUALITY_GATE.md`](./QUALITY_GATE.md),
   [`DESIGN_SYSTEM.md`](./DESIGN_SYSTEM.md), [`SHOPS.md`](./SHOPS.md), [`SPENDING.md`](./SPENDING.md),
   [`EVENTS.md`](./EVENTS.md), [`CLOUDFLARE_AUDIT.md`](./CLOUDFLARE_AUDIT.md)), і звірити кожне
   твердження з кодом. Довгі документи поділити за [`DOC_GROWTH.md`](./DOC_GROWTH.md), числа
   замінити посиланням на гейт, який їх друкує.
2. **Мертвий CSS.** Прибирати пачками по домену (Page Builder, каталог стилю, прев'ю Telegram,
   аналіз), кожна пачка — окремий коміт із зеленим `npm run check:css`. Клас, який рендерить
   спільний код, лишається: правило живе в `packages/shared/src/styles/`.
3. **Хлам у репозиторії.** Кожен новий предмет проходить одну перевірку: чи є в нього читач.
   Немає — видаляється рішенням власника; є — отримує місце в документі теми. `content/` не
   чіпаємо: це імпортовані дані, і гейт навмисно виводить їх з бюджету документації.
4. **Cloudflare.** Інвентаризація з доказами в [`RESOURCE_PLAN.md`](./RESOURCE_PLAN.md), далі
   видалення **після ОК по кожному ресурсу**. `*-prod` не чіпаємо: це заготовка майбутнього
   прода, а не сирота.
5. **Легасі-хвіст D1.** Кожен рядок [`DB_LEGACY.md`](./DB_LEGACY.md) закривається рішенням:
   лишити (і тоді рядок переїжджає в [`DATA_MODEL.md`](./DATA_MODEL.md) як нормальна схема) або
   `DROP` через `wrangler d1 execute` після звірки даних.
6. **Карта репо для агента.** Скрипт `agent-map` у `scripts/` генерує карту «файл → експорти → власник
   теми → документ», `npm run check:map` тримає її свіжою в CI, `AGENTS.md` лишається точкою
   входу. Індекс не дублює код: тіла функцій у ньому немає, лише адреси.
7. **Гейт істини.** Семантичні перевірки в `scripts/check-docs.mjs`: легасі-слова в прикладах
   (таблиця без оголошення в реєстрі), вписані виміряні числа, документ за межею як борг із
   причиною. Правило, яке не перевіряється, зникає через місяць — тому перевірка є частиною
   кроку, а не побажанням.

## Що чекає рішення власника

- **Кожен новий предмет хламу окремо** (крок 3): видалення незворотне, тому рішення ухвалює
  власник, а не агент.
- **Кожен Cloudflare-ресурс окремо** (крок 4). Видалення R2 незворотне; D1 має Time Travel, але
  це не привід прибирати без звірки.
- **Легасі-колонки й таблиці D1** (крок 5): зайва колонка нічому не шкодить, а `DROP` — це
  незворотний крок заради чистоти.
- **Гейт на `scripts/migrations`** (крок 7): правило «застосований файл не редагується» й заборона
  дампів персональних даних описані в [`D1_OPS.md`](./D1_OPS.md), але нічим не стережуться.
  Пропозиція — перевірка в `check:db`: `INSERT INTO users`, `telegram_json`, `chat_id` у
  `scripts/migrations/*.sql` = червоний.

## Як крок вважається закритим

- зелений `npm run verify` (той самий набір, що в джобі `checks`);
- рядок кроку зникає звідси, а не обростає поясненням;
- коміт, пуш у `main` і зелений `Deploy` — правило `AGENTS.md` §6.

## Чим цей список неповний

Звірено структуру документації й помітні твердження, але **не** кожен абзац кожного документа;
мертві TS-модулі й експорти не шукали; GitHub поза репозиторієм (issues, PR, артефакти Actions)
не дивилися. Це не «перевірено», доки не перевірено — і саме тому крок 1 іде першим.
