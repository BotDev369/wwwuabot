# Падіння деплою: виявити, назвати причину, не повторити

**Джерело правди:** `scripts/ci-classes.mjs` (реєстр класів) · `scripts/ci-triage.mjs` (розбір
логу й нитка) ·
**тригер:** `.github/workflows/ci-triage.yml` · **нитка:** issue «CI: розбір падінь деплою»

Червоний прогін сам себе не пояснює: у списку видно «Deploy — failure», а крок, правило
й файл лишаються в логах джоби, які ніхто не відкриває. Через це та сама помилка
повторюється тижнями: її бачать, але не **називають**, а без назви немає ні лікування,
ні виміру.

## Що стається після падіння

Нічого не треба запускати руками. `Deploy` завершується — `workflow_run` піднімає
`CI triage`, і той:

1. бере останні прогони `Deploy` і знаходить у них **невдалий крок**, а не просто
   «прогін червоний»;
2. зводить крок до **класу** з реєстру: `coverage`, `comments`, `docs`, `format`,
   `audit`, `deploy-flake`… Клас — це пара «причина + лікування», записана в коді,
   а не в чиїйсь пам'яті;
3. витягує **хвіст логу** невдалого кроку (обрізаючи прибирання раннера, інакше
   замість помилки видно `git config`), тож у звіті лежить справжній рядок: який файл,
   яке правило, яке число;
4. оновлює **одну** нитку в issues: таблиця «клас → скільки разів → що робити»,
   посилання на останні падіння. Другої нитки не буде: канонічна та, що створена
   раніше, решта закривається;
5. перезапускає **тільки транзієнтні** класи (`deploy-flake`, `setup`) і **тільки**
   коли прогін стояв на голові `main`.

Перший зелений прогін закриває нитку. Відкрита нитка = «зараз червоно», і це видно,
не заходячи в Actions.

## Чому перезапуск тільки на голові `main`

Cloudflare пише останнім, хто встиг. Перезапуск деплой-джоби старого коміта залив би
на прод **старіший** код — це відкат, а не лікування флейка. Тому перезапуск
дозволений лише для прогону, чий `head_sha` дорівнює голові `main`, і лише один раз
(`run_attempt < 2`): другий повтор — це вже сигнал про ліміт чи зламаний секрет,
і його треба бачити, а не замазувати.

## Реєстр класів

Таблиця нижче — не копія: вона пояснює, **що означає** кожен клас, а самі регекси й
тексти живуть у `CLASSES` у `scripts/ci-classes.mjs`. Двійник розійшовся б із кодом на
першій правці.

| Клас | Що зламалось |
|---|---|
| `coverage` | новий або змінений файл прийшов без тесту |
| `comments` | блок коментарів понад вісім рядків або мертвий шлях |
| `docs` | документ за межею редагування, мертве посилання, § без дому |
| `format` | файл не прогнано через Prettier |
| `style` | каталог вигляду застарів після правки CSS |
| `audit` | `npm audit` знайшов уразливість `high` |
| `quality` | межа рядків, `alert`/`confirm`, `100vh` без `dvh`, емодзі в UI |
| `css`, `inline` | клас без правила; інлайновий стиль замість токена |
| `db` | таблиця або `CREATE TABLE` поза реєстром схеми |
| `lint`, `typecheck` | ESLint; помилка типів |
| `build`, `bundle`, `tests` | збірка оболонки; бюджет бандла; юніт-тест |
| `deploy-build` | збірка воркера перед деплоєм |
| `deploy-flake` | Cloudflare не прийняв деплой: квота, `5xx`, обрив — **транзієнтний** |
| `setup` | `npm ci`, чекаут, `setup-node` — **транзієнтний** |
| `unknown` | крок, якого немає в реєстрі: це завжди робота — додати клас |

Клас, що повторився тричі й більше, у звіті позначений **«система, не раз»**: один
раз — випадок, три — дірка в процесі, і лікувати треба не прогін, а правило.

## Новий клас

1. Додай запис у `CLASSES` (`scripts/ci-classes.mjs`): `id`, `step` (регекс на назву кроку),
   за потреби `job`
   (у деплой-джобах кроки звуться однаково), `cause`, `fix`, `transient`.
2. Перевір на справжній історії: `node scripts/ci-triage.mjs --runs 40 --logs` —
   клас мусить з'явитися з тим падінням, а не «десь».
3. Рядок у таблиці вище — лише якщо клас описує нову **причину**, а не варіант.

## Превенція: що робить механізм, а що ні

Він **виявляє, називає й прибирає шум** (флейк перезапускається, дублікат нитки
закривається, хвіст логу показує файл). Він **не виправляє код** і не блокує пуш:
більшість класів — це локальні гейти, які мусили пройти до пушу. Тому превенція
двошарова:

- **правило:** перед пушем — `npm run verify` (див. `QUALITY_GATE.md`), а не вибіркові
  команди;
- **порядок кроків:** гейт, що падає найчастіше, стоїть у джобі `checks` перед
  збірками, щоб та сама помилка коштувала хвилини, а не повного прогону.

Разом це не робить CI бездоганним — воно робить кожне падіння **названим** і дешевим.
