# Design System

> Токени та правила вигляду. Обоє оболонок (`web-platform-dev`, `web-admin-dev`) — через
> `@wwwuabot/shared/styles/`. Класи-кирпичики каркаса — `AGENTS.md` §3; їх перелік тут **не**
> дублюється: джерело правди сам CSS і `npm run check:css`.
>
> **Номери правил стабільні:** на них посилається код у коментарях, тож правило **замінюється**, а не
> зникає.

## Токени

`packages/shared/src/styles/tokens.css`, перевизначення за брендом — `apple.css` / `android.css`.

| Токен | Призначення |
|---|---|
| `var(--bg-page)` | Фон **екрана**: плоский колір, той самий, що йде нативному хрому Telegram (`= var(--chrome-header-bg)`). Ним малюються `body`, `.wb-app`, `main`, зони `.page-zone*`, `.wb-splash`, `.wb-auth` |
| `var(--bg-home)` | Градієнт-підкладка **поверхонь** (картки, панелі). Площину екрана ним НЕ малюємо: плоский колір клієнта не дорівняє градієнту — був би шов |
| `var(--bg-0)` … `var(--bg-4)` | Поверхні від підкладки до hover |
| `var(--text-primary)` / `--text-secondary` / `--text-muted` | Текст: основний / другорядний / підказка |
| `var(--text-inverse)` | Текст на акцентній плашці |
| `var(--accent)` / `--accent-hover` / `--accent-dim` / `--accent-soft` | Акцент: база / hover / плашка / підкладка під фокус |
| `var(--user-bg)` / `var(--user-text)` / `var(--user-accent)` | **Три кольори користувача** (фон / основний / акцент). Ставить `applyColors()` інлайном на `<html>` разом із `data-colors`; читає `user-colors.css`. Це **єдина** палітра продукту: усе нижче (поверхні, текст, акцент, межі, статусні підкладки, хром) виведено з цих трьох через `color-mix()` |
| `var(--user-on-accent)` | Підпис на акцентній плашці (`= var(--text-inverse)`): той із фону / основного, хто далі від акценту (`onAccentColor()`) |
| `data-colors-mode` (на `<html>`) | Схема, **виведена з фону** (`colorsMode()`): вибирає тіні, скрим, `color-scheme` і світлі варіанти статусних кольорів |
| `var(--border)` / `--border-subtle` | Межі: помітна / ледь видима |
| `var(--surface)` / `--surface-hover` / `--surface-active` / `--surface-overlay` | Поверхні карток, стани й скрим |
| `var(--field-bg)` / `var(--field-ring)` | **Поле вводу**: колір і м'яка тінь по краях. Межу поля малюють саме вони, а не лінія. Світла / темна схема — у `themes.css` |
| `var(--chrome-header-bg)` / `--chrome-bottom-bg` | Нативний хром Telegram: шапка клієнта і смуга під футером; синхронізує `shared/app/telegram-chrome.ts`. З трьома кольорами користувача це рівно `--user-bg` (плоский hex — саме тому він іде клієнту як є). Наші смуги (`.wb-app-header`, `.wb-topbar`, `.wb-tabbar`) малюються тими самими токенами на 91% і **без** ліній та тіней |
| `var(--green)` / `var(--red)` / `var(--yellow)` (+ `--*-dim`) | Успіх / небезпека / попередження |
| `var(--font-ui)` / `--font-display` / `--font-mono` | Основний / заголовковий / моно |
| `var(--radius-xs)` … `--radius-xl`, `--radius-full` | 2 / 4 / 6 / 8 / 12 / 16px і 9999px (пілюлі) |
| `--sp-0` … `--sp-16` | Відступи 4px-кроком |
| `--btn-pad-y`, `--btn-pad-x` | Мірки кнопки: `padding` пише лише базове `.wb-btn`, з цих токенів (правило 16) |
| `--shadow-*`, `--elevation-*`, `--duration-*`, `--ease*` | Тіні, рух і пружина |
| `--z-dropdown` < `--z-sticky` < `--z-overlay` < `--z-modal` (400) < `--z-tabbar` (**1100**) < `--z-toast` (1200) | Шари: футер вище за модалки (правило 12) |
| `--sidebar-w` / `--sidebar-w-collapsed` / `--drawer-w` / `--scrim` | Геометрія навігації (однакова в обох оболонках) |
| `--topbar-h` / `--nav-bar-h` / `--tab-bar-h` | Висоти смуг; `--tab-bar-h` = `--nav-bar-h` + `--safe-bottom` (не перевизначати третім числом) |
| `--safe-top` / `--safe-bottom` | Краї екрана: `env(safe-area-inset-*)` + `--tg-safe-area-inset-*` від Telegram |
| `--max-content` | Максимальна ширина контенту |

> `--safe-*` != 0 лише тоді, коли в `index.html` є `viewport-fit=cover`. Без нього контент
> залазить під виріз і індикатор «додому» — і виглядає це як «десь дизайн поламався».

## Правила

1. Тільки класи `.wb-*` — жодних власних `.btn`, `.modal`, `.card`.
2. Тільки токени — жодних хардкоджених hex і піксельних `border-radius`.
3. **Емодзі в UI заборонені** — `<Icon />` зі shared.
4. **Дропдауни заборонені** — повноекранна поверхня (`MenuModal`).
5. Бренд — атрибут `data-brand` на `<html>` (Apple / Material).
6. Колір — **три кольори користувача** (`data-colors` + `data-colors-mode`): фон / основний /
   акцент, усі обов'язкові. Світла чи темна — не вибір, а наслідок світлості фону. Палітру з них
   виводить `user-colors.css`; другої таблиці «слот → токен» у TS немає.
7. Нові файли беруть `<Icon />` — жодних локальних `const ico`.
8. **Нативні `alert` / `confirm` / `prompt` заборонені**: на iOS у WebView Telegram їх не
   рендерять, тому кнопка мовчки нічого не робить. Тільки `useDialog()`.
9. Дії підписують `<Icon />`, а не символами: `↑`, `↓`, `✕` не масштабуються з `size`, не читаються
   скрін-рідером і виглядають по-різному у шрифтах.
10. Якщо клас рендерить спільний код (`packages/ui`), його стилі живуть у
    `packages/shared/src/styles/` — не в `index.css` однієї оболонки.
11. **Клас без правила — це дефект, а не стиль.** `class="wb-mt-3"` без `.wb-mt-3` не ламає ні
    збірку, ні тести: відступ просто не з'явиться. Стереже `npm run check:css` (клас у розмітці ↔
    правило; спільний код не стилізований лише в одній оболонці), борг — `scripts/css-baseline.mjs`
    (тільки зменшувати).
12. **Каркас складають із кирпичиків, а не малюють.** Хром оболонки — `.wb-app*`, `.wb-nav*`,
    `.wb-tabbar*`, `.wb-topbar*`, `.wb-page*`, `.wb-auth*`, `.wb-splash`, `.wb-profile*`,
    `.wb-handle*` (`app-chrome.css`); перелік — `AGENTS.md` §3. Сторінка, що скролиться всередині
    панелі, додає `.wb-page-scroll`: каркас панелі тримає `overflow: hidden`. Профіль починається
    з імені на платформі (`.wb-handle*`), решта — `.wb-profile-note` / `-details` / `-summary` /
    `-subfields`; чи ім'я можна правити, вирішує **наявність обробника збереження**, тому вигляд в
    обох оболонках однаковий.
    Глобальний футер (`.wb-tabbar`, `TabBar` з `@wwwuabot/ui/nav`) — теж кирпичик: рівні слоти, дія
    «+» в центрі, профіль праворуч. Активний розділ підсвічує **власний знак**, а не тло: оболонка
    віддає залитого близнюка контурної іконки (`iconActive`, напр. `home` → `home-solid`). Футер
    `position: fixed`, тож під ним мусить бути місце (`.wb-tabbar-layout` / `.wb-app-body--tabbar`).
    Він **хром**: жодна модалка його не закриває (`--z-tabbar` 1100 > `--z-modal` 400), і кожна
    лишає під ним місце (`html:has(.wb-tabbar) .wb-modal-overlay`). Вибір іншого розділу закриває
    композер (це стан оболонки), «+» його перемикає.
13. **Композер («+» у футері) — одна спільна модалка, а не екран кожної оболонки.** Розмітка — ті
    самі `.wb-modal*`, що в `useDialog()`, плюс `.wb-composer*`. Вкладка й кнопка вкладення — **та
    сама клітинка** (одне правило: без рамки й тла, радіус, підсвічення на дотик), її мірка,
    проміжок і відступ від краю — локальні змінні `.wb-composer` (`--composer-cell`, `-gap`, `-pad`),
    тому ряд вкладень стоїть на рівні першої вкладки. Колонка вкладок тримає `--composer-col`
    (68px) на всій ширині: підпис, який рветься посеред слова, — дефект розкладки, тому підпис
    `nowrap` + еліпсис і ніколи не заїжджає на поле. **Ліній усередині немає** — розділяє простір;
    немає й пояснювального абзацу під полями (підпис і кнопка вже кажуть, що робити). Дії
    («Закрити» / «Зберегти») — **останній ряд тіла вкладки** (`.wb-sheet-actions`, той самий
    кирпичик, що в перегляді нотатки), не прибитий футер: модалка росте зі вмістом, а
    `margin-top: auto` тримає їх унизу, поки місце є.
    Поля мають власну розкладку (`.wb-composer-field` / `-input` / `-tags`), але **поверхню** — зі
    спільного кирпичика поля: одне правило перелічує `.wb-input`, `.wb-select`, `.wb-textarea` і
    обидва поля композера та малює їх `--field-bg` + м'яким `--field-ring`. Поле видно кольором і
    **розмитим контуром**, а не лінією; бренди більше не нав'язують цим класам рамку через
    `!important` (Apple і Android додають лише радіус і мірки). Кожне поле має **підпис над собою**
    (`.wb-label`) — саме він каже, де що, у модалці без рамок.
    Кожне поле тримає **мінімум 16px** (`max(16px, 1em)`) **у власному правилі**, не в спільному
    списку: iOS WebKit збільшує всю сторінку, коли фокус потрапляє в поле з меншим шрифтом, а
    пізніше правило одного поля тихо перекриває спільну межу — так цей дефект повертався двічі.
    Стереже `packages/shared/src/styles/fields.test.ts` (читає CSS усього продукту).
    Поле нотатки — три рядки заввишки, далі скролиться, і росте двома способами: `resize: vertical`
    на десктопі та разом із текстом на тачі (`useAutoGrowField`, зі стелею; розтягнуте рукою не
    зменшує). Хештеги — чипи й поле в тому самому ряду (`.wb-composer-tag*`): тег закінчує пробіл,
    кома або Enter, Backspace у порожньому полі знімає останній; правила — чисті функції в `tags.ts`.
    Вкладки — дані (`tabs.ts`): нова вкладка це рядок у списку, не нова розмітка. Вкладка, чийого
    інтерфейсу ще немає, показує, що там буде, а дія без реалізації відповідає `useDialog()`, а не
    мовчить на телефоні. Слот дії у футері несе власний `onSelect` (`ShellTab.onSelect` +
    `withPrimaryAction`): «створити» — це дія, а не маршрут, тож вигадувати їй `href` не треба.
14. **Блоки Page Builder ще стилізовані інлайном** (`packages/ui/src/blocks/*`), і `wb-block-*` не
    мають правил, тому `data-brand` і `data-theme` до них не доходять. Переносити їх у `.wb-block-*`
    у `components.css` — відкрита робота; борг записаний у `scripts/css-baseline.mjs` і тільки
    зменшується.
15. **Розділювач — не лінія.** Ні шапка модалки, ні футер картки, ні рядок таблиці не малюють
    штрих: місце відділяє простір, а структуру тримають **поверхня** (колір картки, шапки таблиці,
    смуга парних рядків), **м'яка тінь** або сам контрол (залитий чип, залита кнопка, поле з
    `--field-bg`). Рамка лишається лише там, де вона — не прикраса, а зміст: індикатор, пунктир
    порожнього слота, кільце фокуса/помилки. Правило спільне для всіх шарів — і `components.css`, і
    `app-chrome.css`, і брендів: бренд — це характер (радіус, мірки, скло), а не повернення ліній.
16. **Мірки кнопки — токени, а не приватний `padding` бренду.** Розмір задають `--btn-pad-y` /
    `--btn-pad-x`, і `padding` пише лише базове правило `.wb-btn` — з них. Apple і Android володіють
    характером (пілюля vs 20px, шрифт, вага) і задають токени. Стежить
    `packages/shared/src/styles/buttons.test.ts`: падіння — на `padding`, що не є парою токенів, на
    брендовий `min-height` понад 44px і на токен понад 20×12px.
17. **Повноекранна поверхня — один кирпичик, і меню профілю — його другий користувач.** Поверхня —
    `.wb-sheet` / `.wb-sheet-head` (тінь замість рамки, відступи під safe-area, радіус телефону);
    композер тримає власні `--composer-*`. Меню (`.wb-menu-body`, `.wb-menu-list`, `.wb-menu-item`
    (+ `--soon`), `.wb-menu-item-icon` / `-text` / `-label` / `-hint` / `-check`, `.wb-menu-account*`)
    рендерить спільний `MenuModal` (`@wwwuabot/ui/menu`) — оболонка дає лише список пунктів. Рядок
    — **дотикова поверхня на всю ширину** (`--field-bg`, без рамки): палець мусить влучати будь-де
    на рядку. Рядок, чийого екрана ще немає, каже це **до** дотику (`status: "soon"` + підказка під
    підписом) і відповідає `useDialog()`. `selected` малює галочку, бо вибране — стан, а не перехід.
    Профіль і панель теми — **вигляди однієї** модалки (кнопка «назад» є лише там, де є куди
    вертатись), ніколи не модалка над модалкою.
    Розкладку пунктів вибирає оболонка (`MenuModal` → `layout`): **рядок** (типове) — там, де його
    читають (вибір вигляду, вибір тегів), бо рядок несе пояснення; **плитки по дві в ряду**
    (`.wb-menu-blocks` / `.wb-menu-block*`) — там, куди тицяють: у меню профілю напис знають
    напам'ять, тож смуга на всю ширину лише розтягувала б список. Заглушка лишається чесною і в
    плитці — але **одним словом** (`wb-badge wb-badge-neutral` «Скоро»): абзац під назвою робив
    плитки різної висоти, а повне пояснення й так живе в підписі кнопки й у діалозі; галочка вибору
    переїжджає в кут. Іконка розділу, який працює, — **акцентна**, заглушки — нейтральна: у сітці
    однакових плиток інакше не видно, що з неї вже відкривається.
    Вміст можна притиснути до низу (`MenuModal` → `align`): порожнеча тоді під заголовком, а пункти —
    у **зоні пальця**. Притискає `margin-top: auto` в першого блоку, а не `justify-content: flex-end`,
    який у тіла з прокруткою обрізав би початок вмісту.
    Блок над списком (`MenuModal` → `header`) — те, що не є пунктом: у виборі тегів це пояснення
    вибору, у профілі — **облікові картки** (`.wb-menu-account` → `-card` / `-text` / `-label` /
    `-avatar` / `-initial` / `-name` / `-sub`). Telegram і портал — два різні джерела про одну
    людину (AGENTS.md §2), тож і дві картки, і кожна веде в профіль, а не до розділу. Смугами вони
    стояти не можуть: у смузі картка читалася б як ще один пункт меню, тож типово це дві колонки
    (картка — портрет), і вони **ділять вільний простір над собою** — рости більше нічому, бо пункти
    мають свою висоту. Друга розкладка (`--rows`, вибір людини) — те саме тіло картки рядком: один
    набір розмітки, два класи, а не два набори. Стежить `packages/shared/src/styles/menu.test.ts`.
    Поверхня вміє бути **на весь екран** (`MenuModal` → `fullscreen`): міняються краї (`.wb-modal--screen`
    парою класів — так медіа-запит телефону не виграє за порядком), заголовок може стояти по центру
    (`titleAlign`), а «закрити» переїхати в **смугу внизу** (`closePlacement` + `footer`, `.wb-sheet-bar`) —
    там же, де палець, і поруч із перемикачем вигляду (`.wb-segmented`, сегмент — планка пальця).
    Смуга — **сестра тіла** з `flex-shrink: 0`, а не останній рядок у тілі: у тіла `overflow-y: auto`,
    і вихід, що їде разом із вмістом, зникає саме тоді, коли його шукають. Місце під футером
    застосунку лишається навіть на весь екран — футер хром і малюється над модалкою.
18. **Нотатки — один спільний екран, і його вигляд — чисті функції.** Список, смуга керування й
    перегляд живуть у `@wwwuabot/ui/notes` (кирпичики `.wb-note*`), оболонка вирішує лише **чиї**
    нотатки та куди їх писати (`createNotesApi` зі своїм транспортом). Пошук, фільтр, сортування й
    групування — один виклик `buildGroups(notes, view, now)` без React: тут помилка виглядає як
    «нічого не знайдено», а не як зламаний код. Тому: пошук вимагає **всі** слова запиту (теги в
    базі — без `#` і в нижньому регістрі), фільтр має три стани («усі» / «без хештегів» / вибрані
    теги, і нотатка мусить мати **кожен** — вибір звужує), групи «за днями» рахуються від
    **локальної** опівночі, і `now` приходить аргументом. **Типово груп немає** (`groupBy: "none"`),
    а титул групи має сенс **лише коли груп кілька**. Вибори не випадають списком (правило 4):
    кожен відкриває ту саму поверхню `MenuModal`, вибране позначене галочкою.
    Шапка сторінки й смуга їдуть разом і **лишаються на видноті** (`.wb-page-sticky`, спільний
    кирпичик каркаса): список довгий, і без цього пошук зникав рівно тоді, коли знайшлось шукане.
    Тло шару — **непрозоре** (`--bg-page`), бо під ним їде вміст.
    Смуга — **спільний кирпичик** `@wwwuabot/ui/collection` (`CollectionToolbar`; свої варіанти й
    слова дає екран), і це **один ряд, який не переноситься** (`.wb-tools-bar`): пошук ліворуч,
    чотири клітинки-знаки праворуч, мірка ряду одна на всі контроли (`--tools-row-h`, 32px — не
    планка пальця 44px: чотири контроли в ряд, і високий ряд забирав би в списку більше екрана, ніж
    сам список). Три знаки — вибори, четвертий (`.wb-tools-btn--toggle`) — **перемикач** «розгорнути
    / згорнути всі»: діє одразу й показує стан сам (`aria-pressed` + заливка `--accent-dim`).
    Розгорнутість — стан **екрана** (`openIds` + `onToggle`), а не картки.
    Поле пошуку в спокої завширшки зі свій підпис («Пошук») і розкривається (`--open`) на фокус або
    запит; на дотик заливка з **розмитим контуром** (`--tools-search-glow`) з'являється навколо
    **місця, де пишуть**, а не навколо іконки. Чипи вибраного стоять **окремим рядом під смугою**
    (`.wb-tools-chips`): вони не клітинки керування, а те, що ці клітинки змінили. ✕ у полі — свій
    (`.wb-tools-search-clear`), бо нативний у WebView малюється окремою коробкою. Склад чипів —
    чиста функція (`viewChips` у нотаток, `buildViewChips` у спільному модулі). Вибраних тегів може
    бути кілька, тож чип має **кожен окремо** (`toggleTagFilter` перемикає **один** тег, порядок
    сталий — за абеткою; прибраний останній вертає до «усі», бо порожній вибір виглядав би як
    фільтр, який нічого не фільтрує). Дотик у пікері тегів тому **не** закриває поверхню — закриває
    ✕ у шапці, а над списком стоїть `.wb-menu-hint`, бо без нього множинний вибір читався б як
    одноразовий. Знаки різні навмисно (`sort` — порядок, `layers` — групи, `hash` — хештег). Стан
    смуги стереже `NotesToolbar.test.tsx` — він читає й CSS, тож перенос, заливка в спокої або мірка
    ряду понад 32px провалюють тест, а не тихо повертаються.
    Картка — **акордеон із двома рядками інфо, і всі закриті**: рядок 1 — початок тексту (він і
    забирає вільне місце, обрізається однією лінією, а переноси згортаються в пробіли) і дата з
    часом, рядок 2 — хештеги. Дата й хештеги **тихіші** за текст, але тихіші **кольором**, а не
    кеглем: обидва підписи — `--text-sm`, а різнить їх колір (штамп `--text-muted`, хештег
    `--text-secondary`), бо `--text-xs` на телефоні не читався. Хештег у картці — **підпис, а не чип**
    (`.wb-note-tag` — власний кирпичик): бренди задають чипу свої мірки з `!important`, і рядок
    хештегів виходив удвічі вищим за рядок із текстом. **Знайдений** хештег (чиста
    `foundTags(tags, view)`) стоїть **акцентним кольором** — у стовпчику однакових підписів око не
    бачить, за що зачепився пошук; акцент тут колір, а не вага. Нічого не шукали — нічого й не
    знайдено (порожній список): акцент каже про дію, а не про наявність. Проміжок між двома рядками
    інфо — найменший (`--sp-1`), бо це один підпис під одним. Голова картки — кнопка на всю ширину
    (палець дістає будь-де), а тіло розкритої картки несе повний текст, обидві дати й дії — тіло
    всередині кнопки дало б кнопки в кнопці. Редагує **той самий** композер (`initial` із `id`), а
    підтвердження видалення дає оболонка: картка віддає дії нагору (`onEdit` / `onDelete`).
    Вигляд списку — **спільний кирпичик** `@wwwuabot/ui/collection` (`CollectionViewSwitch` плюс
    чиста модель): рядки чи **картки-превью** й скількома колонками (1 / 2). Кирпичик саме спільний,
    а не «для нотаток»: той самий вибір знадобиться товарам, новинам і постам, тож у ньому немає ні
    React-стану, ні слова «нотатка». Клітинка (`.wb-collection-tool`) — та сама, що у вкладок
    композера, а мірку бере від ряду (`--cell`). Сам вибір — вибір (правило 4): поверхня `MenuModal`
    із трьома варіантами і галочкою на вибраному; знак у клітинці сталий, а поточний вибір видно
    знімним чипом («Картки · 2»). Колонок у рядків немає — і це функція (`sameCollectionView`), а не
    намір: інакше «рядки · 1» і «рядки · 2» були б двома станами з галочкою на двох підписах одразу.
    Розкладку тримає **кирпичик**, а не список (`.wb-collection--rows` / `--cards` + `--cols-N`).
    Плитки — **та сама розмітка** з іншою розкладкою, і розкриття лишається тим самим: картка росте
    на місці, тож «розгорнути всі» не перестає працювати від зміни вигляду.
19. **Колір задає людина трьома кольорами — і ніяк інакше.** Три обов'язкові слоти («Кольори
    теми»: фон / основний / акцент) живуть у `localStorage` (`wwwuabot-colors`) і на `<html>` як
    `--user-*`; панель — спільна `ThemeColorPanel` (`@wwwuabot/shared/components/theme`), яку обидві
    оболонки показують в одній і тій самій поверхні (`.wb-sheet`: платформа — вмістом меню профілю,
    адмінка — кнопкою «Тема»). Панель — три **закриті** акордеони (`ThemeSection`) від загального до
    часткового: **Стиль** (характер Apple / Material — уся оболонка на один дотик), **Кольори теми**,
    **Готові палітри** (палітри не налаштування, а швидкий старт, тож вони внизу й закриті).
    «Порожніх не буває» — це функція (`isCompleteColors`), а не намір: без усіх трьох вибір не
    зберігається й не застосовується. Вибір окремого кольору **не вимагає знання кодів**
    (`ColorEditor`): спершу **зразки** (сітка 12 відтінків × 3 світності + смуга від чорного до
    білого, `COLOR_CHART` / `COLOR_SHADES`), потім **системна палітра** (`input type="color"` — уся
    гама, піпетка), і аж потім точність: повзунки H/S/L із намальованими доріжками і код кольору.
    Панель відкривається **не порожньою**: поки вибору немає, слоти стартують із кольорів, які вже
    на екрані (`activeColorsFromDom`), а порожній слот (після «Прибрати») малюється пунктиром, бо
    «не вибрано» — це стан, який видно до дотику. Кольори **застосовуються живцем** (неповний вибір
    — ні), а «Скинути» вертає брендову палітру й показує її в слотах. Стан збереження панель називає
    **рядком** (`.wb-theme-status`: «Незбережені зміни» → «Збережено на цьому пристрої»), бо кнопка,
    що просто сіріє, читається як «не спрацювала»; тому кнопок дві — «Зберегти» лишає панель
    відкритою, «Зберегти і закрити» виходить через `onClose` від оболонки. Вихід без збереження
    вертає палітру **зі сховища**, а не зі стану компонента.
20. **Контакти: контакт — запис, а лінк — його поле; приєднання — два кроки.** Екран (`/contacts`)
    зводить спільний `@wwwuabot/ui/contacts` (кирпичики `.wb-contact*` у власному `contacts.css` — як
    `theme-panel.css`, бо це цілісна деталь), а список улаштований **як «Нотатки»**: групи, акордеони
    й та сама **спільна смуга керування** (`CollectionToolbar`, чипи — `buildViewChips`, правила
    хештега й днів — `tags.ts` / `days.ts`), контакти підставляють лише свої варіанти й слова.
    Закритий рядок показує **два рядки інфо**: номер, ім'я з датою-часом зміни і стан словом («без
    лінка» / «лінк чекає» / «зайшов у бота» / «приєднався»), а хештеги — підписами (`.wb-contact-tag`,
    не чип; **знайдений** тег стоїть акцентом). **Дотик розгортає рядок**: у тілі — етапи
    (`.wb-contact-stage*`, «Запрошено» → «Зайшов у бота» → «Зайшов на платформу»), лінк **за станом**
    (немає коду → «Створити лінк»; код є → діплінк і «Копіювати»; за лінком уже прийшли → ані того,
    ані того), обидві дати, глибина гілки («Залучив(ла) ще N») і дії, а **дії віддаються нагору**
    (`onEdit` / `onDelete` / `onMakeLink` / `onCopyLink`): буфер, діалоги й підтвердження належать
    оболонці (та сама межа, що в нотатках). **Правка — у формі** (`ContactSheet`, та сама поверхня
    `.wb-sheet`), і там **лише власні поля** (ім'я, `@username`, хештеги, примітки) — **поля
    «Telegram ID» немає**: id людини власник не знає, його бачить бот (`docs/DATA_MODEL.md`).
    **Числа — три пари «знак + цифра» (Всього / Бот / Платформа) у ряд із назвою екрана**, останнім у
    тому ж рядку — **коло з «+»** (`.wb-page-add`; акцентне тло лишається **тільки** в нього — воно й
    робить його головною дією, коли підпису немає). Знаки різні навмисно (`users` / `bot` / `globe`):
    три однакові силуети читались би як одне число. Заливки й підписів у шапці **немає** — плашка
    важила б більше за саму цифру; слово лишилось у `dt` і сховане (`.wb-contact-stat-word`: `1px`,
    `clip-path: inset(50%)`, а **не** `display: none`), бо сам знак числа не називає; число й знак
    стоять **акцентом**. Числа йдуть **за спаданням**: «Всього» рахує **усі записи** (і контакт без
    лінка), а «Бот» і «Платформа» — **людей, а не картки** (два лінки на одну людину дають два записи
    й одного в лійці; той, хто на платформі, порахований і в «у боті»). Різницю видно в списку, де
    дубль підписаний «та сама людина, що …» (`.wb-contact-twin`). «+» питає ім'я, створює запис,
    **одразу складає лінк, кладе його в буфер** і відкриває форму. Заголовок екрана — **«Контакти»**
    (правило 21: префікса «Мої» немає ніде), а **«+» стоїть і в «Нотатках»** — та сама мірка й те
    саме правило: у шапці місце дії, а не підпису, і назву кнопки несе `aria-label`.
21. **Підписів «Мій / Мої» немає — ніде.** Ні в пунктах меню («Контакти», а не «МоїКонтакти»), ні
    в футері («Дати», а не «МоїДати»), ні в заголовках екранів, ні в назвах усередині блоку. Меню й
    екран відкривають **зі свого профілю**, тож приналежність і так очевидна, а префікс відсував
    саме те слово, за яким пункт упізнають і за яким він стає в абетку. Пункти меню стоять **за
    абеткою (А→Я)**, а не за важливістю: сталий порядок не залежить від того, хто додав пункт
    останнім. Стежать `profile-menu.test.ts` (абетка в локалі `uk` і відсутність префікса) і
    `TabBar.test.tsx`.
