# Аудит якості: оцінка за 10 критеріями

**Це знімок на 12.09.2026, а не поточний стан.** Числа в ньому навмисно не перераховувались:
оцінка потрібна була один раз — щоб знати, **де** борг, а не щоб міряти прогрес. Живі числа —
[`CONSOLIDATION_PLAN.md`](./CONSOLIDATION_PLAN.md) §0. Що змінилось після знімка: зник цілий
домен `sites` (разом із ним і «найризикованіший модуль» §2.5), таблицю `pages` і `scenarios-admin`
скасовано, тестів стало **241 у 26 файлах** замість 182 у 22, поріг `npm audit` піднято до `high`.
Тому нижче **дві правди в одному документі** — оцінка (12.09) і поправки (13.09), позначені 🔹.

**Підсумок: 57,9% порядку** (578,5 з 1000 зважених балів). Документація — **88%** (§4).
Борг зосереджений не там, де його зазвичай шукають: процес, CI й документація — сильні;
тягнуть вниз **вимірюваність**, **тести критичних шляхів**, **дизайн-система всередині
блоків** і **мобільна доступність**.

## 0. Як саме мірялося (щоб цифру можна було перевірити)

| Що | Як |
|---|---|
| Мертвий код | обхід графа імпортів від точок входу (`main.tsx`, `worker.ts`, `router.tsx`, `exports` у `package.json`), включно з динамічними `import()` |
| Спільний код ↔ CSS | множина класів, які рендерить `packages/ui`, проти множини селекторів усіх `.css` |
| Мертвий CSS | клас, якого немає в `src/` **навіть як підрядок** (це **нижня** оцінка) |
| Покриття тестами | не coverage-інструмент, а граф: скільки модулів `src/` імпортується з тестів |
| Вага бандла | `ls -la` по `dist/` після `vite build` обох оболонок |
| Уразливості | `npm audit` |

**Чого тут немає:** вимірювань у рантаймі, візуальної перевірки, E2E, пентесту, сценаріїв на
пристроях. Саме тому найменш надійні критерії — мобільність (6) і продуктивність (9).

## 1. За якою системою оцінюється

Рубрика зібрана з визнаних моделей, адаптованих під цей проєкт (Cloudflare Workers + React + D1,
мобільний TMA — пріоритет №1):

| Джерело | Що взято |
|---|---|
| **ISO/IEC 25010 (SQuaRE)** | maintainability, security, reliability, performance, usability/accessibility |
| **CISQ / OMG** | мертвий код, дублювання, розмір модулів, складність |
| **SIG/TÜViT** | розмір файлів (200/400 рядків) як поріг читабельності |
| **WCAG 2.2 AA** | семантика, фокус, розмір тап-таргетів |
| **`AGENTS.md` §3, §4, §7** | локальні норми (кристалевість, `SELECT *`, нативні діалоги, клас без CSS) |
| **DORA / CI-зрілість** | гейти, що блокують деплой; відтворюваність збірки |
| **Bundle budget** | вага чанка — окремий критерій для TWA |

Перевірка дає **2** (норма), **1** (частково) або **0** (ні). Оцінка критерію = набрані бали ÷
максимум × 10; підсумок = сума (оцінка × вага) ÷ 100. **Вага навмисно не рівна:** мобільність і
тести важать по 15 — це те, що бачать користувачі, і те, що ловить регресії.

## 3. Де ми на шкалі зрілості

| Рівень | Стан |
|---|---|
| **L2 — керований** | ✅ правила діють для частини коду |
| **L3 — визначений** | ✅ правила писані, гейти блокують деплой (CI, Prettier, lint, тести) |
| **L4 — вимірюваний** | ⚠️ частково: з'явились ліміт рядків, клас без CSS, нативні діалоги, `100vh`, емодзі. **Немає** бюджету бандла й порогу покриття |
| **L5 — оптимізуючий** | ❌ |

**Головний висновок знімка лишається чинним:** проєкт виглядав як L3, але **ніщо не заважало
йому котитися назад у L2**, бо якість ніде не мірялась автоматично. Саме тому 44 класи без CSS
і 15% мертвого коду прожили місяці: гейти перевіряли, що код *компілюється*, а не що він
*потрібен*.

## 6. Межі цієї оцінки (читати перед цитуванням)

1. **Немає рантайм-вимірювань** — продуктивність оцінена за вагою файлів, не за профілем.
2. **Немає візуальної перевірки** — висновки про верстку з CSS і розмітки, не з екрана.
3. **Мертвий CSS — нижня оцінка:** склеєні рядками імена (`wb-${x}`) статично невидимі.
4. **Ваги — рішення, не істина** (15 для мобільності обрано свідомо: TWA = телефони).
5. **Прода немає** — «надійність» міряється тестами й гейтами, не поведінкою під навантаженням.
6. **Числа — знімок 12.09;** 🔹-позначки показують, що вже не так.
