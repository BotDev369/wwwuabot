# 🤝 Регламент внесення змін (CONTRIBUTING.md)

> **Для кого цей документ:** Розробники, контриб’ютори та AI-агенти (Claude, Gemini, Qwen, ChatGPT тощо).  
> **Мета:** Збереження високої якості коду, відсутність регресій, запобігання дублюванню та гарантія проходження CI/CD воріт.

---

## 🧭 Головні правила монорепозиторію

1. **Єдине джерело істини:**
   - Спільна бізнес-логіка, утиліти роботи з датами, парсинг, типи та спільні константи **завжди** розміщуються у `packages/shared/`.
   - Повторювані UI-компоненти та віджети сторінок розміщуються у `packages/ui/`.
   - **Суворо заборонено дублювати** функції між воркерами (`bot-dev`, `api-dev`, `web-platform-dev`, `web-admin-dev`). Якщо вам потрібна функція, яка вже є в іншому воркері — винесіть її в `packages/shared`.

2. **Нульова толерантність до `any`:**
   - У монорепозиторії досягнуто стан **0 `any`**.
   - Не використовуйте `any`. Використовуйте точні типи, дженерики або `unknown` із type-guards.

3. **Єдиний кореневий lock-файл:**
   - Монорепозиторій використовує npm workspaces.
   - **Ніколи** не створюйте вкладених `package-lock.json` чи `*.lock` у підпапках. Усі залежності встановлюються виключно з кореня через `npm install`.

## 🚦 Обов’язкові перевірки перед комітом / PR (Quality Gates)

Перед кожним пушем або відкриттям Pull Request виконайте наступні команди з кореня репозиторію:

```bash
# 1. Запуск усіх unit-тестів (Vitest)
npm test

# 2. Повна перевірка типізації у всіх воркспейсах
npm run typecheck

# 3. Перевірка лінтером ESLint
npm run lint
```

> **Увага:** Якщо хоча б одна команда завершується з помилкою, такий код **не можна** пушити в гілку `main`.

## 📝 Конвенція назв комітів (Conventional Commits)

Використовуйте стандартний формат повідомлень комітів:

```
<type>(<scope>): <короткий опис>
```

- **Типи (`type`):**
  - `feat`: нова функціональність для користувача
  - `fix`: виправлення помилки або бага
  - `refactor`: зміна структури коду без зміни функціональності
  - `test`: додавання або оновлення тестів
  - `docs`: оновлення документації чи коментарів
  - `chore`: оновлення залежностей, конфігурацій збірки тощо
- **Області (`scope`):**
  - `shared`, `ui`, `bot`, `api`, `web`, `admin`, `ci`, `docs`

**Приклади:**
- `feat(builder): add customizable button block to page builder`
- `fix(api): validate incoming user dates in UsersService`
- `refactor(shared): unify datetime formatting across workers`
- `test(bot): add unit tests for screen routing`

## 🤖 Регламент для AI-агентів

1. Перед виконанням задач обов’язково ознайомтесь із `AGENTS.md` та `docs/PRODUCT_VISION.md`.
2. Не видаляйте існуючу робочу функціональність заради "спрощення".
3. Нові функції обов’язково покривайте тестами у `*.test.ts`.
4. Зберігайте кодування UTF-8 без BOM.
