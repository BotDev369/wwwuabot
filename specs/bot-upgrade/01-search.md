# 01. Пошук по пошукових словах

## 1.1 Де живуть слова

| Що | Стан | Факт |
|---|---|---|
| Колонки `search_terms` у сторінках і товарах | ✅ вже є | `platform_pages` — [`tables.ts:225`](../../packages/shared/src/database/tables.ts), `shop_products` — [`tables.ts:268`](../../packages/shared/src/database/tables.ts). Тип `TEXT NOT NULL DEFAULT '[]'`, всередині **JSON-масив фраз** |
| Автогенерація слів із назви, slug і транслітерації | ✅ вже є | `searchTermsFrom` у [`packages/shared/src/search/index.ts`](../../packages/shared/src/search/index.ts); товар отримує слова при створенні — [`products.service.ts:220`](../../api-dev/src/services/shop/products.service.ts) |
| Правило «активний товар без слів не зберігається» | ✅ вже є | [`products.service.ts:183`](../../api-dev/src/services/shop/products.service.ts) → `no_terms` (400) |
| Правило для **сторінок** (без слів не публікується) | ⬜ треба додати | у збереженні сторінки перевірки немає: індекс просто бере слова з назви ([`search/index.ts:45`](../../api-dev/src/services/search/index.ts)) |
| Редагування слів з інтерфейсу | ⬜ треба додати — ❗ [питання 1](./07-questions.md) | адмінка показує слова **тільки для читання**: `searchTermsLabel` у [`PlatformPagesPage.tsx:26`](../../web-admin-dev/src/pages/platform/PlatformPagesPage.tsx). | Аркуш для вичитки | ✅ вже є | [`keywords.md`](./keywords.md); тест звіряє кожен синонім із матчером |

**Що таке «пошукове слово».** Це не тег і не ключ, а **фраза, якою люди називають річ**: «галя
шоп», «галяшоп», «galya shop», «зелена аптека», «іван чай». Регістр, пробіли, дефіси й апострофи
значення не мають — їх знімає нормалізація (1.2). Синоніми — це і є alias-и (див. 1.3), окремої
таблиці псевдонімів не треба.

## 1.2 Нормалізація варіантів

Обидва боки — індекс і запит — проходять **ту саму** функцію
[`normalizeSearchKey`](../../packages/shared/src/search/normalize.ts). Порядок: нижній регістр →
`NFC` → прибрати `’ ʼ ' \` ´` → лишити тільки `0-9 a-z а-я ї і є ґ` → **українська транслітерація в
латиницю** (`г→g`, `я→ya`, `и→y`, `ж→zh`, `ч→ch`, `ш→sh`, `щ→shch`, `х→kh`, `ь→""`) → прибрати все,
що не `0-9a-z`. Латиниця з діакритикою згортається окремою таблицею (`š→sh`, `č→ch`, `ž→zh`,
`á→a` …).

Тому всі ці запити — **один ключ** `galyashop`:

| Запит | Ключ після нормалізації |
|---|---|
| `Галяшоп` | `galyashop` |
| `Галя Шоп` | `galyashop` |
| `Galyashop` | `galyashop` |
| `GalyaShop` | `galyashop` |
| `GALYASHOP` | `galyashop` |
| `галя-шоп` | `galyashop` |
| `Galyá Shop` | `galyashop` |

**Одруківки.** Окремий «fuzzy-фолбек» не потрібен як другий індекс: відстань редагувань рахується
на льоту (`editDistance`) і спрацьовує **лише** для ключа від 5 символів з відстанню ≤ 1
([`match.ts:65`](../../packages/shared/src/search/match.ts)). `galyashp` → `galyashop` ✓ (1 правка),
`галяшоп` → `галяшоп` ✓ (0), `галяш` — не «схоже», а коротший збіг за входженням (окремий, вищий
бал). Це свідомо вузько: широкий fuzzy на кількох десятках записів дає більше хибних карток, ніж
знахідок.

## 1.3 KV: ключі й індекси

| Що | Стан | Факт |
|---|---|---|
| Один ключ на всю версію | ✅ вже є | `SEARCH_INDEX_KEY = "search:v2"` — [`search/index.ts:19`](../../api-dev/src/services/search/index.ts); стара форма не живе поруч із новою |
| Namespace | ✅ вже є | `CONTENT_KV`, id `bda7a5fca58b4fbda87d75105d558ebf` — один і той самий у [`bot-dev/wrangler.toml:17`](../../bot-dev/wrangler.toml) і [`api-dev/wrangler.toml:16`](../../api-dev/wrangler.toml). Другого KV не заводимо |
| Формат значення | ✅ вже є | `{ builtAt, entries: SearchEntry[] }`; у записі — `kind` (`page`/`product`), `id` (тільки товар), `slug`, `shopSlug`, `title`, `subtitle`, `description` (≤240 символів), `price`, `photo` (абсолютна адреса шлюзу), `terms[]`, `href` — [`match.ts:11`](../../packages/shared/src/search/match.ts) |
| Окремі ключі-індекси на слово | ⬜ не потрібно зараз | індекс — **один** `KV.get` на запит: 20 сторінок + 21 товар, це дешевше за десятки дрібних читань і не має проблеми «індекс розійшовся з індексом». Якщо рядків стане тисячі — план Б: `search:v2:term:<ключ>` → `id[]`, але це нова версія формату, а не «оптимізація на око» |
| Alias-мапінг | ✅ не потрібен | псевдоніми — це елементи `terms[]`; нормалізація робить їх рівними один одному. Окрема таблиця alias-ів додала б друге джерело правди |
| Кеш індексу в пам'яті інстансу | ✅ свідомо немає | [`search.repository.ts`](../../bot-dev/src/modules/search/search.repository.ts) читає KV щоразу: свіжість важливіша за одне читання |
| Хто пише | ✅ вже є | `api-dev` — власник сторінок і товарів: [`rebuildSearchIndex`](../../api-dev/src/services/search/index.ts) |

**Перебудова — тільки по факту зміни.** Розкладу немає: `crons = []` у
[`api-dev/wrangler.toml`](../../api-dev/wrangler.toml).

| Тригер | Стан |
|---|---|

| Збереження / видалення **сторінки** та правка слів | ⬜ треба додати — тієї ж кнопки поки що досить, але це ручний крок |

**Що не індексується:** приватні сторінки (`is_public = 0` з власником), неактивні, заблоковані
власники, товари закритих магазинів — відбір у SQL, не в рендері
([`search/index.ts:155`](../../api-dev/src/services/search/index.ts)).

## 1.4 Як шукаємо і як сортуємо

Бал рахує [`scoreOf`](../../packages/shared/src/search/match.ts):

| Бал | Умова |
|---|---|
| 100 | назва точно дорівнює запиту |
| 90 | запит точно дорівнює одному з пошукових слів |
| 85 | назва **починається** з запиту |
| 80 | запит (≥3 символи) входить у назву або назва в запит |
| 75 | якесь слово **починається** з запиту |
| 70 | запит (≥3 символи) входить у слово |
| 60 | **усі** слова запиту є в назві або словах (порядок не важливий) |
| 40 | одна одруківка (відстань ≤1, ключ ≥5 символів) |

Далі — за балом, при рівності за назвою (`localeCompare("uk")`), і **не більше 5 карток**
(`SEARCH_RESULT_LIMIT`). Порядок — не прикраса: без нього «коти» знаходили б «дівчат-котів» раніше
за «сердитих котів».

**Кілька сторінок з однаковими словами** — нормальний випадок: показуємо всі, хто вліз у п'ять, у
порядку балів. Окремої сторінки «всі результати» немає.

**Нуль збігів** — це відповідь, а не помилка: «Нічого не знайдено», «На платформі немає нічого за
запитом «…»», «Спробуйте написати по-іншому.» ([`search-screen.ts:112`](../../bot-dev/src/modules/search/search-screen.ts)).
Запит і кількість збігів пишуться в лог (`SEARCH sent` / `send failed`), тож нулі видно в Cloudflare
Logs.

**Якщо індексу немає** (KV порожній — свіжий деплой): бот не вигадує відповідь, а йде далі
сценарієм — [`search.handler.ts:31`](../../bot-dev/src/modules/search/search.handler.ts). Лікування —
кнопка «Перебудувати пошук», а не фолбек у коді.
