# Системи: канонічний інвентар

Цей файл — відповідь на питання «а як саме ви це порахували?». Для кожної системи тут
записано: що вона бере з дати, за якою формулою, які якості з цього виходять, що вона
**не** може знати й де результат залежить від невизначеності.

Головне правило: **показник існує тільки тоді, коли його можна перевірити**. Дата без часу й
місця — це не привід вигадувати точність, а привід показати межі.

## Контракт прозорості

| Що | Де живе | Що бачить людина |
| --- | --- | --- |
| `about` | `LensDefinition` | абзац «про систему» в блоці розрахунків |
| `gives`, `limits` | `LensDefinition` | «що бере з дати» / «чого не знає» |
| `source` | `LensDefinition` | «Канон: …» під показниками |
| `parameters` | `SystemRead` (сервер) | таблиця показників дати |
| `undetermined` | `SystemRead` (сервер) | скількох якостей система не визначає |
| `details` | кожен `QualityClaim` | «Як ми це визначили» під рівнем |

Рівень без `details` — це твердження без доказу. Одна система дає **одне** свідчення про
якість: якщо різні показники ведуть до тієї ж якості, лишається сильніше, а ланцюги
об'єднуються — інакше «скільки систем назвали» рахувало б одну систему двічі.

## 1. Західна астрологія (`western`, v2)

**Вхід:** дата. **Момент:** 12:00 UTC, бо часу народження немає.

**Довгота Сонця** — Meeus, *Astronomical Algorithms*, розд. 25:

```
n = JD − 2451545.0
L = 280.46646 + 0.9856474·n
g = 357.52911 + 0.98560028·n
λ = L + 1.915·sin g + 0.020·sin 2g   (mod 360)
```

Похибка формули ≈0.01°. Більша невизначеність — сама дата: за добу Сонце проходить ≈59′.

| Показник | Як рахується | Канон |
| --- | --- | --- |
| Знак | `floor(λ/30)` | тропічний зодіак |
| Градус у знаку | `λ mod 30`, градуси й хвилини | — |
| Декан | `floor(градус/10)`, 1–3 | халдейський порядок управителів |
| Управитель декана | таблиця 12×3 | халдейський порядок |
| Єгипетська межа | таблиця меж Птолемея | *Тетрабіблос* |
| Двадашамша | `floor(градус/2.5)`, знак = знак + зсув | дванадцята частина |
| Стихія | `знак mod 4` | вогонь/земля/повітря/вода |
| Хрест | `знак mod 3` | кардинальний/фіксований/мутабельний |
| Полярність | парність знака | ян/їнь |
| Управитель | сучасний і традиційний | — |

**Якості (9 свідчень):** 3 від знака, 1 від стихії, 1 від хреста, 1 від фази декана, 1 від
управителя декана, 1 від управителя межі, 1 від двадашамші. Кожне свідчення спирається на
**свій** показник.

**Межі доби:** якщо на 00:00 і 24:00 змінюється знак, декан, межа або двадашамша, це
пишеться в показниках і в `details`.

**Чого не знає:** Місяць, асцендент, доми, точні аспекти (потрібні час і місце); події не
пророкує.

## 2. Піфагорійська нумерологія (`numerology`, v2)

**Згортка.** Кожна частина дати згортається окремо; 11, 22 і 33 лишаються майстер-числами,
поки це можливо. Кармічні числа — **13, 14, 16, 19**: вони фіксуються, якщо трапляються як
проміжна сума до фінального згортання.

| Показник | Формула | Особливість |
| --- | --- | --- |
| Життєвий шлях | `reduce(M + D + Y)`, де M, D, Y — окремі згортки | майстер-числа лишаються; ланцюг показується |
| Число дня | `reduce(day)` | 29 → 11, 22 → 22 |
| Ставлення | `reduce(M + D)` | як людина підходить до життя |
| Особистий рік | `digitalRoot(month + day + digits(currentYear))` | завжди 1–9; залежить від поточного року |
| Пік 1 | `reduce(M + D)` | вік 0 … 36 − корінь шляху |
| Пік 2 | `reduce(D + Y)` | +9 років |
| Пік 3 | `reduce(П1 + П2)` | +9 років |
| Пік 4 | `reduce(M + Y)` | до кінця життя |
| Виклики 1–4 | `|M − D|`, `|D − Y|`, `|C1 − C2|`, `|M − Y|` | для викликів M, D, Y — вже 1–9; 0 — «всі теми» |

**Якості:** шлях — 3–4 якості; день, ставлення й рік — по одній темі; кожен пік і кожен
виклик — по одній; кармічний борг — одна зона роботи. Після об'єднання одна якість — одне
свідчення.

**Межі:** число зрілості та числа імені потребують імені (не питаємо); особистий рік
залежить від календарного року; жодних прогнозів подій.

**Джерело:** піфагорійська школа в редакції Ганса Декоза й Метью Гудвіна.

**Формули.**

```
рік:  sexagenary = (solarYear − 4) mod 60; stem = mod 10; branch = mod 12
місяць: branch = (2 + monthIndex) mod 12
        stem = ((yearStem mod 5)·2 + 2 + monthIndex) mod 10   // П'ять тигрів
день:  sexagenary = (JDN + 49) mod 60; stem = mod 10; branch = mod 12
```

**Якість (8 свідчень):** тварина року (3), стихія року (1), полярність року (1), місяць як
сезон (1), елемент дня (1), гілка дня (1).

**Перевірка:** 2000-01-01 = 戊午 (У-У); 1949-10-01 = 甲子 (Цзя-Цзи); 1980-03-03 = Ґен-Шень,
місяць У-Інь (до Цзін Чже), день Ї-Хай.

**Чого не знає:** стовп години (потрібен час), приховані стовбури й сила елементів; межа дня
береться за календарною датою.

## 4. Цолькін (`mayan`, v2)

**Кореляція GMT 584283** (Томпсон): 0.0.0.0.0 = JDN 584283; 2012-12-21 = JDN 2456283.

```
days = JDN − 584283
кін   = ((days + 159) mod 260) + 1
тон   = ((days + 3) mod 13) + 1
печать = (days + 19) mod 20          // 0 = Іміш … 19 = Ахау
трецена = floor((кін − 1) / 13) + 1
хвиля = перший кін трецени = 13·(трецена − 1) + 1
довга лічба = baktun.katun.tun.uinal.kin
```

**Перевірка:** 2012-12-21 = 4 Ахау, кін 160, трецена 13, хвиля «1 Кабан»; 2000-01-01 = 11 Ік,
кін 102; 1980-03-03 = 9 Кауак, кін 139.

**Якість (4–5 свідчень):** печатка (3), тон (1), хвиля (1, рівень 2 — це фон, не риса).

**Чого не знає:** володар дня й годинний цикл без часу; довга лічба й календарне коло —
окремі цикли, не прогноз; інша кореляція зсуває дату на 2 дні.

## Чому не «мільйон систем»

Система потрапляє в портрет, тільки якщо є **формула**, яку можна перевірити; **таблиця**
правил із джерелом; **межі**, які ми показуємо. Реєстр може описувати більше систем, ніж має
формулу — але тоді вони лишаються довідкою й не дають свідчень. Краще чотири глибокі, ніж
тринадцять «тяп-ляп».

## Що далі (не входить у цю версію)

- ведична система (накшатра й доша потребують часу/місця);
- «ідеальний час для події» — окремий вектор, не продовження рис людини;
- стовп години й приховані стовбури Ба-Цзи.
